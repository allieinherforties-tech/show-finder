# show-finder AGENTS.md

## What this repo is

The kid-situation episode finder: a static-first web app that helps parents
find Apple TV+ Kids and Family episodes by what their kid is going through.
The build spec (Blueprint art_40Zp3MgH) and the Reconciled Build Plan
(art_wsIoHoLR) govern scope and quality. This file covers repo mechanics.

## House rules

1. **Zero em dashes and en dashes in generated copy and UI strings.** In text
   we author (UI copy, docs, reports), restructure the sentence instead of
   swapping the character. `test/copy.test.mjs` enforces this for public/ and
   src/. Curated source rows in data/source are verbatim workbook data; the
   build flags dashes there in `data/search/validation-report.json` and never
   rewrites them. The curation thread owns those fixes.
2. **The emotion vocabulary is binding.** Canonical terms live in
   `src/vocabulary.mjs`. Unknown emotion terms fail the build (add a synonym
   mapping or widen the list deliberately). Trait words route out of the
   emotion column.
3. **Field key is `coping`; the UI label is `resolution`.** Never rename the
   data field, never display the key.
4. **Story-first synopses.** The display synopsis is per_story_synopsis when
   present. A segment 2 row never opens with segment 1's story.
5. **No TMDB calls and no external images in the serving path in Phase 1.**
   Artwork arrives in Phase 2 through the swappable artwork layer.

## Commands

```
npm run fetch   # refresh data/source dumps from the project workbooks (needs the obvious CLI)
npm run fetch:artwork  # TMDB stills and posters into data/source/tmdb-artwork.json (needs TMDB_API_KEY, offline build step)
npm run build   # normalize, validate, embed, emit data/search artifacts
npm test        # node --test
npm run lint    # eslint
npm start       # serve on :3000
node scripts/smoke.mjs   # end to end check
```

## Data flow

`data/source/*.json` are committed dumps from the project workbooks (written
by `npm run fetch`). Two more committed dumps feed Phase 2:
`data/source/tmdb-artwork.json` (stills and posters, written by
`npm run fetch:artwork`) and `data/source/apple-links.json` (verified Apple
TV show and episode ids, transcribed from the deep-link findings).
`data/search/search-artifact.json` is the versioned, byte-reproducible search
artifact (hash stamped; CI verifies a clean rebuild matches it).
`data/search/search.db` is generated by the build, gitignored. The server
loads both at startup and never touches the network for data.

## The artwork layer and deep links

One flag controls the swap. `ARTWORK_MODE=tmdb` (the default) renders
attributed TMDB episode stills and posters on result cards;
`ARTWORK_MODE=text` reverts to Phase 1 text-only cards. Flipping the flag and
restarting is the entire deploy change.

- **Hotlink pattern.** Cards reference image.tmdb.org directly at TMDB
  rendition sizes (w780 stills, w342 posters), original aspect ratio, no
  crops, filters, or overlays. References rebuild weekly with the catalog,
  far under the 6 month cache ceiling, and purge with one rebuild.
- **Attribution.** The TMDB logo and the verbatim notice live in the
  About/Credits section of the page. The build fails when artwork mode is on
  and either is missing.
- **Deep links.** Each card carries the canonical tv.apple.com URL: episode
  level where the findings document verified the id, show page otherwise,
  no link when the series has no verified pattern. The build fails on any
  URL that does not match a verified pattern shape.
- **Version hash.** Artwork and link URLs are part of every story row, so
  they ride the same sha256 stamp as story content.

## Phase 2 boundaries

Artwork mode ships on: cards carry attributed TMDB episode stills (series
poster as fallback) in an About/Credits-attributed layer, swappable to
text-only with one flag. Watch buttons link to verified tv.apple.com URLs,
episode level where the id is verified, show page otherwise, and rows with
no verified pattern get no button rather than an invented id. The embedder
is still the deterministic local hash embedder; the EmbeddingGemma-class
model swap point is unchanged (`registerEmbedder` in
`src/search/embedder.mjs`). Emoji stays in the schema and out of the UI,
per the v1.1 deferral.
